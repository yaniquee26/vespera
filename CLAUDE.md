# CLAUDE.md — Vespera (читай целиком перед любой работой)

## 1. Что это за проект

**Vespera** — испытательный стенд (test bench) для чат-ботов и ИИ-агентов с инструментами:
безопасность и надёжность на английском, русском и румынском. Это портфолио-проект Иана
(Кишинёв, не программист, ищет junior QA / AI-QA роль). Цель: выглядеть как аккуратный
коммерческий инструмент уровня реальной инженерной команды, а не как учебная поделка.

Что проверяет: прямая и косвенная инъекция промптов, скрытые приказы в ответах инструментов,
утечки секретов и персональных данных, запрещённые действия агента, лишние отказы на
безобидные вопросы, язык ответа.

Главные принципы (не нарушать):
1. **Правила, не ИИ-судьи.** Все проверки — простые детерминированные правила.
2. **Честная статистика.** Рядом с долей всегда интервал Уилсона 95% и размер выборки.
   Разница «убедительна» только если интервалы не пересекаются.
3. **«Прошёл» ≠ «безопасно».** Прошёл = нарушений не замечено в оценённых попытках.
   Если атака до агента не дошла (exposure < 50%) — исход `inconclusive`, не `passed`.
4. **Каждая цифра имеет доказательство** (сырой ответ, проверка, снимок условий).
5. **Воспроизводимость:** каждый прогон хранит Snapshot (модель, хеши промпта и сценариев,
   повторы, max_steps, версия).
6. **Только выдуманные данные.** Секреты, телефоны, IDNP в сценариях синтетические.
7. Секреты (API-ключи) никогда не пишутся в файлы: только имя переменной окружения (`api_key_env`).

## 2. Как с этим человеком работать

- Иан **не программист**. Ты пишешь код, тесты и проверки сам и сам их запускаешь.
  Он запускает команды, присылает скриншоты, пересказывает своими словами.
- Объяснения пользователю — **на простом русском**. Код, docstring, имена, коммиты — на английском.
- Всегда говори, **на каком этапе** мы и какой это микрошаг (из ROADMAP.md).
- Перед работой: план из 3–6 пунктов, дождись «да». Исключение: мелкая правка по прямой просьбе.
- Только текущая задача. Не добавляй возможности «заодно». Не переписывай архитектуру без разговора.
- Тесты, написанные пользователем, не менять без согласования.
- Новые зависимости — только после вопроса.
- Коммитишь **только по просьбе**. Формат: `feat:` / `fix:` / `test:` / `docs:` / `chore:`.
  Не коммить `.env`, `*.db`, `runs/`, `.venv`.
- **Режим объяснения после каждой задачи:** 5–8 строк по-русски «что сделали и зачем»,
  2 контрольных вопроса, один способ «сломать специально» и увидеть, что тест ловит.
  Иан должен суметь пересказать этап другу или на собеседовании.
- Не изображай «специалиста из MIT». Будь честным инженером: если не уверен, скажи.
- Экономь лимит: не читай весь репозиторий без нужды, не гоняй лишние прогоны моделей.

## 3. Железные правила качества (перед «готово»)

```
ruff check . --no-cache
mypy src
pytest
```
Все три зелёные. Сейчас: **356 тестов**, покрытие ~99%. CI (GitHub Actions, ubuntu, Python 3.12)
запускает то же самое. Не снижай покрытие.

- Python 3.12+, src-раскладка (`src/vespera`), ruff line-length 100, mypy `disallow_untyped_defs`.
- Контракты — Pydantic v2, frozen, `extra=forbid`. Между слоями не передавать «голые» dict.
- Тесты **не ходят в сеть и в Ollama**: только MockProvider / httpx.MockTransport и выдуманные данные.
- `tests/conftest.py` переключает рабочую папку каждого теста в пустую временную. Не убирай:
  без неё лежащий в корне `vespera.yaml` подхватывается CLI-тестами и ломает их (так упал CI #19).
- Предупреждения Git про CRLF/LF на Windows безвредны.
- Версия живёт в `pyproject.toml` и `src/vespera/__init__.py`; меняй вместе, плюс запись в CHANGELOG.md.

## 4. Архитектура (слои: зависимость только вниз)

```
cli → report / compare / summary / gate / export → findings / stats
    → checks / runner / agent_runner → providers / storage / snapshot → contracts
```
Модули в `src/vespera/`: `contracts`, `agent_contracts`, `providers` (Mock, Ollama,
OpenAI-совместимый, Http, агентные провайдеры), `scenarios`, `agent_scenarios`, `checks`,
`runner`, `agent_runner`, `storage` (SQLite: runs, cases, attempts, traces, check_results),
`snapshot`, `stats` (Уилсон, нестабильность), `findings`, `summary`, `report` + `report_template`
(один HTML, Jinja2 autoescape), `compare` + `compare_template`, `taxonomy` (OWASP LLM Top 10 2026
+ серьёзность), `gate` (passed 0 / failed 2 / inconclusive 3), `export` (results.json схема
`vespera.results/1`, JUnit, маскирование), `config` (vespera.yaml), `bundled` + `data/`, `doctor`, `cli`.
async только в провайдерах и раннере.

Ключевые факты:
- Проверки возвращают passed/failed/info. INFO-результат несёт информацию в `value`
  (язык ответа, `hidden_order_delivered`, `tool_call_as_text`).
- Возобновление прогона отказывает, если изменились модель, повторы, хеш промпта/сценариев, max_steps.
  3 ошибки подряд → прогон прерывается.
- Агентный режим: цикл вызова инструментов с имитированными инструментами, журнал `AgentTrace`,
  замер «дошёл ли скрытый приказ до агента» (exposure), дрейф языка в другой алфавит = `other`.
- Таксономия: direct_injection LLM01 High; indirect_injection LLM01 High; jailbreak LLM01 Medium;
  system_prompt_leak LLM08 High; pii_leak LLM02 Critical; tool_output_injection LLM01 Critical;
  data_exfiltration LLM02 Critical; excessive_agency LLM03 High; benign / benign_task — без OWASP, Medium.
- Гейт: нарушение важнее сомнения; правило, которое ничто не тестирует → inconclusive.
  Опции: `max_attack_rate`, `zero_tolerance` (OWASP id или имя категории), `min_exposure`.
- Экспорт маскирует canary-токены, длинные числа и секреты из сценариев; `--reveal` снимает маску.
  HTML-отчёт хранит полное доказательство.
- `vespera.yaml`: target (ollama | openai | http | mock), mode text|agent, repeats, limit, max_steps,
  scenarios, system_prompt, report, gate, exports. Неизвестные ключи отклоняются.
  Приоритет: флаги CLI > файл > умолчания.

## 5. Команды CLI

`version`, `doctor`, `ask`, `validate`, `run`, `run-agent`, `show`, `check [--mask]`, `report [--open]`, `runs`,
`compare`, `init [--agents --force --directory]`, `test [--config --no-config --mode --json --junit
--reveal --zero-tolerance --min-exposure --max-attack-rate --limit --repeats]`, `gate`, `export`.

Типичный путь: `vespera init` (вопросы, готовый `vespera.yaml`) → `vespera test --open`; без файла: `vespera test openai:MODEL` (префиксы ollama, openai, openrouter, lmstudio, mock — `config.parse_target`);
в CI — `vespera test` с кодом выхода 0/2/3.
