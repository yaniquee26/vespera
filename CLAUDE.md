# CLAUDE.md: правила работы над Vespera

Vespera: фреймворк проверки надёжности LLM на RU/RO/EN. Полная спецификация в `SPEC.md`, текущие задачи в `TASKS.md`. Читай только нужный раздел, не весь файл.

## Как работаем

- Делай ТОЛЬКО текущую задачу из `TASKS.md`. Ничего «заодно».
- Сначала предложи план из 3–6 пунктов и дождись подтверждения.
- Тесты пишутся вместе с кодом. Тест, который написал пользователь, не изменяй без согласования.
- Перед завершением запусти `ruff check .`, `mypy src` и `pytest`, покажи результат.
- Небольшие коммиты, сообщения вида `feat: ...`, `test: ...`, `docs: ...`. Коммить только по просьбе.
- Новые зависимости только после вопроса и объяснения, зачем.

## Режим объяснения (обязательно)

Пользователь учится и должен суметь пересказать каждый модуль. После каждой задачи:
1. Объясни по-русски простыми словами, что сделано, в 5–8 строках.
2. Назови 2 вопроса на понимание.
3. Предложи способ сломать код специально, чтобы увидеть, что тест это ловит.

## Технические правила

- Python 3.12+, раскладка `src/vespera/`, пакетный менеджер pip и venv, настройки в `pyproject.toml`.
- Код, имена, docstring и сообщения коммитов на английском. Объяснения пользователю на русском.
- Pydantic v2 для всех контрактов. Без «сырых» словарей между слоями.
- Слои зависят только сверху вниз: cli → reporting/compare → evidence/stats → checks/runner → providers/storage → contracts.
- Асинхронность только в провайдерах и раннере. Один запрос к модели за раз.
- Тесты не обращаются к сети и к Ollama, только `MockProvider` и временные файлы.
- Данные в сценариях и тестах только выдуманные. Никаких реальных телефонов, ключей и документов.
- Не логируй содержимое `.env` и секреты. Не коммить `.env`, `*.db`, `runs/`.

## Чего не делать

Не добавляй функции из раздела 2 `SPEC.md`. Не переписывай архитектуру без обсуждения. Не усложняй: простое решение лучше умного. Если задача неясна, спроси.

## Экономия лимита

Не перечитывай весь репозиторий. Не вставляй большие файлы в ответ. Для крупных задач предложи разбить на части.
